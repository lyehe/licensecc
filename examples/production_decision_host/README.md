# Production Decision Host Example

This example shows the production-shaped client path:

- local license verification
- enforced host-integrity policy
- required online verification with primary and backup verifier URLs
- persisted revocation-floor load/store through `lcc_acquire_license_decision()`

## Build and run

This is a standalone consumer of an installed Licensecc package; it is not a
target in the repository-root build. First complete the
[offline-first tutorial](../../doc/tutorials/offline-first-license.rst), which
installs the `test` project under `build/dev-debug/install` and issues the
matching sample license. The commands below start in the Licensecc repository
root. Linux needs a libcurl development package; OpenSSL Crypto is optional
unless request-proof signing is enabled. On Windows/MSVC, CMake uses libcurl
when available and otherwise selects the native WinHTTP implementation.

Starting directory: the Licensecc repository root. Shell: Bash on Linux or
PowerShell 7 on Windows/MSVC.

### Linux (Bash)

```bash
repo="$PWD"
cmake -S examples/production_decision_host -B build/production-decision-host \
  -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_PREFIX_PATH="$repo/build/dev-debug/install" \
  -Dlicensecc_DIR="$repo/build/dev-debug/install/lib/cmake/licensecc" \
  -DLCC_PROJECT_NAME=test
cmake --build build/production-decision-host
"$repo/build/production-decision-host/production_decision_host" \
  --license "$repo/build/dev-debug/projects/test/licenses/quickstart.lic" \
  --floor-store "$repo/build/production-decision-host/revocation-floor.txt" \
  --verifier-url https://primary.example.workers.dev \
  --verifier-url https://backup.example.workers.dev
```

### Windows/MSVC (PowerShell 7)

```powershell
$repo = (Resolve-Path ".").Path
cmake -S examples/production_decision_host -B build/production-decision-host `
  -G "Visual Studio 17 2022" -A x64 `
  "-DCMAKE_PREFIX_PATH=$repo/build/dev-debug/install" `
  "-Dlicensecc_DIR=$repo/build/dev-debug/install/cmake/licensecc" `
  -DLCC_PROJECT_NAME=test
cmake --build build/production-decision-host --config Debug
& "$repo/build/production-decision-host/Debug/production_decision_host.exe" `
  --license "$repo/build/dev-debug/projects/test/licenses/quickstart.lic" `
  --floor-store "$repo/build/production-decision-host/revocation-floor.txt" `
  --verifier-url https://primary.example.workers.dev `
  --verifier-url https://backup.example.workers.dev
```

With a valid license and a verifier that returns an accepted signed assertion,
the process exits 0 and prints lines beginning with:

```text
decision=allow event=license OK
online_verified=true revocation_floor_loaded=true revocation_floor_stored=true tamper_enforced=true
```

Replace the example verifier URLs with your deployed HTTPS verifier. The
floor-store path above stays under `build/`; do not point it at a source-root
or shared location.

Verifier URLs must use HTTPS by default. For a local test verifier, pass
`--allow-insecure-http-for-test`. The `--fail-host-integrity-for-test` switch
forces the host-integrity callback to deny so integration tests can verify the
fail-closed path.

The floor store records the maximum accepted `revocation_seq` for the current
project, feature, and license fingerprint. Load or store failures deny the
decision. The example does not print raw hardware identifiers, secrets, or full
license fingerprints.

For verifier deployments that enable request proof-of-possession, wire a
provider into `OnlineClient::request_proof_provider`. The shared online callback
helper builds the canonical payload from the nonce-bound `LccOnlineRequest` so
the host can sign it with a registered device key. Roll this out with the
verifier in `REQUEST_SIGNATURE_MODE=soft` before moving selected entitlements to
`required`.

When this example is built with OpenSSL Crypto, or with the Windows CNG fallback
enabled, it can use a file-backed development key generated by the verifier
package. From the repository root in PowerShell 7, use the single installed
workspace and an ignored root build directory:

```powershell
$repo = (Resolve-Path ".").Path
$keyDir = "$repo/build/production-decision-device-key"
npm run device-key --workspace @licensecc/cloudflare-licensing-backend -- generate --out-dir $keyDir
& "$repo/build/production-decision-host/Debug/production_decision_host.exe" `
  --license path/to/license.lic `
  --floor-store path/to/revocation-floor.txt `
  --verifier-url https://primary.example.workers.dev `
  --request-proof-device-key-id sha256:KEY_ID_64_HEX `
  --request-proof-private-key "$keyDir/device_private_key.pkcs8.pem"
```

Replace `KEY_ID_64_HEX` with the id reported by the generation command.

That file-backed key path is intentionally for integration tests and bootstrap
work. Production hosts should keep the same request-proof callback shape but
store and use the private key through the platform key store or hardware-backed
provider where available.

Host-integrity probes are best-effort signals running on a customer-controlled
machine. Treat them as tamper-resistant telemetry and policy inputs, not proof
that the host is trustworthy.
